# v0.2.0 live checks — 2026-09-15

Four user-like checks of the real engine on this machine, one network run each.
Nothing here is a fixture: every number is wall-clock or copied from the run's own
output. Task 8.6b of the phase-8 plan; these are the release evidence for v0.2.0.

- machine: Darwin arm64 (Apple Silicon), `CoreMLExecutionProvider` for NLI
- models: `BAAI/bge-small-en-v1.5` + `cross-encoder/nli-deberta-v3-base` (already downloaded)
- cache: **warm** from the v0.1 live runs and task 8.7 — `proofpath cache` reported
  `256 sources, 38413 chunks, 287 verdicts` and `7 resolutions, 6 retraction checks`
  before check 1, so checks 1–3 are cached runs of the same draft as
  `docs/eval/2026-09-12-v0.1-live.md` §1; check 4 is a new document
- config: `permissions.network = allow`, `permissions.install_browser = ask`, a contact
  address set
- the tree under test is the unreleased v0.2.0 working tree. Checks 1 and 3 were first
  run before the version bump (part C of the same task) and printed `0.1.0`; both were
  **re-run after it** and the version strings below are from the re-runs — the SARIF
  document was otherwise byte-identical apart from `properties.elapsed`, and the banner
  differs in the version alone. The numbers of checks 2 and 4 are the originals

started in a **pseudo-terminal** (Python `pty.fork`, 100 × 40, `TERM=xterm-256color`)

`pyte` terminal emulator (`uv run --with pyte`, not added to the project). This is the

`run_test`. The session: `/check tests/data/draft-live.md` → wait for the coverage
line → `/check` alone → `Esc` → `/cancel 1` → `/quit`. Exit status **0**.

Then, in order:

  `paste a file path, a URL, or a claim` to **`paste a file path or URL`**.
- `Esc`: the placeholder went back to `paste a file path, a URL, or a claim` — the
  awaiting mode was left, nothing was run.

  running`**; the run block was untouched.

Two things seen on the way, neither a blocker (OPEN-ITEMS 12.6 and 12.7). Neither is
fixable outside `tui/app.py`: the doubled marker is that file's `FindingLine` label
(`f"[{n}] {raw}"` over a `raw` that keeps its printed marker), and the note's position
is the true event order — `verify` emits `loading models …` *inside* the Verifying
stage, after `StageStart`; the CLI only looks different because it prints `StageEnd`:

- Each finding row prints the marker twice — `[7] [7] Marchetti, …` — because
  `Reference.raw` keeps the printed marker (a Phase 5 decision) and the row prefixes
  the number again. The CLI's diagnostic prints the entry once.
- The `loading models …` note is drawn *after* the `Verifying` row it belongs before;
  the row is created when the stage starts and the note arrives while it runs.
