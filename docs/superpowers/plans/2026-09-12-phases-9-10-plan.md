# Phase 9 — judge layer → v0.3.0


## Task 9.1 — judge client, prompt templates, cost accounting

Spec §11 / §11.1 (LLM budget; Groq default `openai/gpt-oss-120b`, Gemini and Ollama
alternatives, all OpenAI `chat/completions` shape; key from env/`.env`, never stored or
printed; ~7k-token batches under Groq's 8K TPM; 1 request/minute tolerated). Existing
`src/proofpath/judge.py` has the provider presets, `ApiKey`, `resolve_api_key`, `check()`.
User rule: prompts live in template files, not in code; API calls wrapped with retry+backoff.

## Prompts — `src/proofpath/prompts/` (packaged: add `[tool.hatch.build.targets.wheel]`
`include` if needed so `.md` files ship; verify with `uv build` + `unzip -l`)
- `review.md`: system + user template (`string.Template`, `$placeholders`; braces are free
  for the JSON example). Input: a numbered list of items, each `id`, `claim`, `passage`,
  `verdict` (the local label + tier). Instruction: for each item answer only from the passage;
  `label` ∈ `SUPPORTED|REFUTED|NEI`; a one-sentence `rationale` quoting the passage words that
  decide it; never invent facts; output strictly `{"opinions": [{"id", "label", "rationale"}]}`.
- `summarize.md`: input = the finished markdown report; output: 3–5 plain sentences a human
  can act on (counts, the most serious finding with its page, the coverage caveat); it must
  not add claims or verdicts not in the report.
- `judge.load_prompt(name: str) -> string.Template` via `importlib.resources.files("proofpath.prompts")`.

## `judge.py` additions
```python
class JudgeUnavailable(JudgeError): ...          # after retries; never fails a run (9.2 catches it)
@dataclass(frozen=True) class Completion: text: str; prompt_tokens: int; completion_tokens: int; model: str
@dataclass class JudgeCost: calls: int = 0; prompt_tokens: int = 0; completion_tokens: int = 0; waited_s: float = 0.0; model: str = ""
def estimate_tokens(text: str) -> int            # len(text) // 4 + 8
class JudgeClient:
    def __init__(self, config: JudgeConfig, key: ApiKey | None, *, client: httpx.Client | None = None,
                 sleep: Callable[[float], None] = time.sleep, max_wait: float = 120.0, timeout: float = 60.0)
    cost: JudgeCost
    def complete(self, messages: list[dict[str, str]], *, json_schema: dict[str, Any] | None = None,
                 max_tokens: int = 1024, temperature: float = 0.0) -> Completion
```
- POST `{base_url}/chat/completions` with `Authorization: Bearer` when a key exists (Ollama:
  none); `response_format={"type":"json_schema","json_schema":{"name":…,"schema":…,"strict":true}}`
  when `json_schema` is given; on HTTP 400 whose body mentions `response_format`/`json_schema`
  retry once with `{"type":"json_object"}`; 429 → sleep `Retry-After` (seconds or HTTP date;
  cap `max_wait`, accumulate `cost.waited_s`), then retry (max 3); 5xx → exponential backoff
  twice; then `JudgeUnavailable`. Never log or include the response body in exceptions
  (existing rule in `check()`); the key never appears in `repr`/errors.
- Usage from the response `usage` block; missing → estimate from the texts.
- Groq requires a key: `JudgeClient(...)` with `key is None` and a provider whose `api_key_env`
  is set raises `JudgeError` naming the env var and the `.env` hint (same text `config check` uses).

## Tests — `tests/test_judge.py` (extend; `respx` on the Ollama preset URL so no key is needed)

`usage`; 400 mentioning `response_format` → second request uses `json_object`; 429 with
`Retry-After: 2` → `sleep(2.0)` recorded, then success, `cost.waited_s == 2.0`; two 503s then

## Task 9.2 — escalation, batching, judgement cache, `--judge`

Spec §9 step 8 ("judge re-checks only low-confidence verdicts, in batches, if enabled"),
§11 (20 claims per prompt, 2–4 calls per paper, 0 calls by default), §11.1 constraints (the
judge never changes a verdict). Depends on 9.1.

## `judge.py`
```python
@dataclass(frozen=True) class JudgeOpinion: label: Label; rationale: str; model: str
@dataclass(frozen=True) class JudgeItem: id: str; claim: str; passage: str; verdict: Label; tier: Tier
class Judge:
    def __init__(self, client: JudgeClient, *, batch_size: int = 20, token_cap: int = 7000) -> None
    def review(self, items: Sequence[JudgeItem]) -> dict[str, JudgeOpinion]   # id → opinion
    @property cost -> JudgeCost
```
- Packing: fill a batch until `batch_size` items or `estimate_tokens(prompt so far) > token_cap`;
  one `complete()` per batch with the `review` template and a strict JSON schema; parse
  leniently: unknown ids, bad labels, missing rationale → skipped and counted in
  `Judge.skipped` with a note; a `JudgeUnavailable` mid-way returns what was gathered so far
  and records `Judge.unavailable = True`. The judge can never raise past `review()`.
- Escalation set: results whose `verdict.tier == "low"` **or** whose label is `NEI` with a
  passage (the model was unsure); never `numeric-mismatch` (rule-decided, score 1.0) and never
  results without a passage (nothing to judge against — rule 1 applies to the judge too).

## `cache.py` — schema v4
Task 8.7 took v3 for the `resolutions` and `retractions` tables and already made the version
comparison numeric (`_version()`, closing OPEN-ITEMS 10.3), so judgements are **v4**.
`judgements(claim_hash, source_id, judge_model, label, rationale, created_at, PRIMARY KEY
(claim_hash, source_id, judge_model))`; `put_judgement`/`get_judgement`; `_migrate_to_v4` adds
the table only (chain it after v3 in `_MIGRATIONS`).
`model_id` untouched, so toggling `--judge` never invalidates verdicts. Judgements are wiped
together with verdicts when a source's text changes (extend the `put_chunks` invalidation).

## `verify.py`
- `Engine.judge: Judge | None = None`; `Engine.default(..., judge: Judge | None = None)`.
- `decide_all` stage 7 "Judging" (`by=f"{provider} {model}"`), after the verdict loop, only
  when `engine.judge` is set: build `JudgeItem`s from the escalation set (cache hits via
  `get_judgement` first), call `review`, store, attach `JudgeOpinion` to the matching
  `ClaimResult.judge` and `Finding.judge` (add the optional field to both, default `None`);
  when the judge disagrees with the local verdict, the finding gains a detail line
  `judge (groq openai/gpt-oss-120b): SUPPORTED — <rationale>`; the local `Verdict` is never
  altered and the finding kind never changes (§11.1). `Report.api_calls = cost.calls`,
  `Report.judge_cost: JudgeCost | None` (add the field), `Report.models["judge"]`.
  `Progress` per batch; `cancel` checked between batches.
- Stage summary: `"12 of 118 verdicts reviewed, 3 calls, 18,402 prompt · 1,210 completion tokens"`;
  when unavailable: `"judge unavailable after N calls; local verdicts stand"` (a `Note`, never a
  failure).

## `report.py` / `ui.py`
Diagnostics show the judge line as `= judge: …`; markdown gets a `judge` column in `## Checked`
and the line under each finding; footer `· 3 API calls` (already there) + `judge: 18,402 prompt
· 1,210 completion tokens` on its own line when non-zero.

## `cli.py`
`check --judge`: build `JudgeClient` from `config.judge` + `resolve_api_key(config.judge.api_key_env)`;
missing key → `error: <env var> is not set (put it in .env; see `proofpath config check`)`, exit 2;
`Engine.default(..., judge=Judge(client))`. Gemini preset → one `hint` on stderr about data use
(spec §11). Judge disabled → report identical minus judge fields, `api_calls == 0` (test).

## Tests
`tests/test_judge.py`: packing (118 items of ~150 tokens → ≤ 6 calls at cap 7000; 20-item
cap), lenient parsing, unavailable mid-way; `tests/test_verify.py`: escalation set membership
(low-tier yes, numeric no, no-passage no), opinions attached without altering verdicts,
judgement cache hit makes zero client calls, cancel between batches; `tests/test_cache.py`:

`tests/test_check_cli.py`: `--judge` without a key → exit 2 with the hint; with a fake judge →
`api_calls` in JSON.

## Task 10.1 — `providers/` package and the academic/web refactor (no behaviour change)

Spec §5.2 `EvidenceProvider` Protocol ("Adding a provider must not require touching the
core"), §5 architecture (academic:// web:// social://). Today `verify.prepare` calls
`Resolver`, `OpenAccess` and `Fetcher` directly; this task moves that behind providers with
the report byte-identical.

## `src/proofpath/providers/__init__.py`
```python
Scheme = Literal["academic", "web", "social"]
@dataclass(frozen=True)
class EvidenceDoc:
    source_id: str; text: str; text_kind: TextKind; state: str; url: str; step: int | None
    notes: tuple[str, ...] = (); from_cache: bool = False
class EvidenceProvider(Protocol):
    scheme: Scheme
    def resolve(self, ref: Reference) -> ResolveResult: ...
    def retraction(self, resolved: ResolveResult) -> Retraction | None: ...
    def fetch(self, ref: Reference, resolved: ResolveResult) -> list[EvidenceDoc]: ...
def provider_for(ref: Reference, providers: Providers) -> EvidenceProvider
    # a raw string that is only a URL (resolve.find_url covers it and nothing else remains after
    # stripping it) → web; a social host (bsky.app, news.ycombinator.com, reddit.com, mastodon
    # instances by pattern, x.com/twitter.com) → social (10.2); else academic
@dataclass class Providers: academic: EvidenceProvider; web: EvidenceProvider; social: EvidenceProvider | None = None
```
## `providers/academic.py` — `AcademicProvider(resolver, oa)`: `resolve` = `resolver.resolve(raw)`;
`retraction` = `resolver.retraction(doi)` when resolved with a DOI; `fetch` = the DOI/arXiv/
no-identifier logic lifted verbatim from `verify.prepare` (`oa.fetch`, `UNVERIFIED (no identifier
to fetch)`), returning one `EvidenceDoc` (or an empty list when nothing could be tried).
## `providers/web.py` — `WebProvider(fetcher)`: `resolve` → `ResolveResult(State.NOT_INDEXED, best=
Candidate(url=…), …)`; `retraction` → None; `fetch` → the ladder (`fetcher.fetch(url)`), grading
by words as `verify` does today.
## `verify.py` — `Engine.providers: Providers`; `prepare` loops `provider_for(ref)` →
`resolve`/`retraction`/`fetch`; the network gate and all stage summaries stay exactly as they
are; `Engine.default` builds `Providers(AcademicProvider(...), WebProvider(...))`.

## Tests
`tests/test_verify.py` outcomes unchanged (run before/after: same findings, states, coverage —
add one golden test that pins a full `Report` from the fakes as JSON via `ui.emit_json` before
the refactor and asserts equality after). New `tests/test_providers.py`: `provider_for` routing

## Task 10.2 — Bluesky and Hacker News, `check --url`, pasted text

Spec §6.2 (Bluesky `public.api.bsky.app` and HN Firebase API, no auth, first-class; where a
post cannot be read the user pastes its text and proofpath verifies the **links inside it**),
§13 `proofpath check --url https://bsky.app/...`.

## `src/proofpath/providers/social.py`
```python
@dataclass(frozen=True) class Post: platform: str; url: str; author: str; text: str; links: tuple[str, ...]; quoted: tuple["Post", ...]; fetched_at: str
@dataclass(frozen=True) class Unreadable: platform: str; url: str; state: str; hint: str
def read_post(url: str, client: PoliteClient) -> Post | Unreadable
```
- Bluesky: `https://bsky.app/profile/<handle-or-did>/post/<rkey>` → `com.atproto.identity.
  resolveHandle` (skip when already a `did:`) → `app.bsky.feed.getPostThread?uri=at://<did>/
  app.bsky.feed.post/<rkey>&depth=0`; text from `record.text`; links from `record.facets`
  (`app.bsky.richtext.facet#link`) and `embed.external.uri`; quoted posts from `embed.record`
  (one level). Per-host interval 0.5 s in `polite.py`.
- HN: `https://news.ycombinator.com/item?id=<n>` → `https://hacker-news.firebaseio.com/v0/item/
  <n>.json`; `url` field + `<a href>` links in `text` (HTML-unescaped, tags stripped); a comment
  (`type == "comment"`) reads its own text; `parent` not followed. Interval 0.5 s.
- 404/deleted/private → `Unreadable(state=fetch.Outcome.UNREACHABLE.value, hint=…)`; rate
  limit/5xx → `UNAVAILABLE`.
- `ingest.from_post(post: Post) -> Document`: `kind="post"`, `name=post.url`; one paragraph per
  post and per quoted post (in order); `references` = the post's links numbered in order of
  appearance (`Reference(number, raw=url, locator)`); every sentence of a paragraph becomes a
  paragraph-scoped claim citing all of that paragraph's links (the post as a whole is what the
  links are supposed to back); a post with no links → no claims, one `Finding`-worthy note
  "no links to verify" (reported by `prepare` as `UNRESOLVED_MARKER`? No — as a document-level
  `PARSE_ERROR`-kind note with title "post carries no links; nothing to verify against").
- `SocialProvider(client, fetcher)`: `resolve` → `NOT_INDEXED` with the URL; `fetch` → the
  ladder on each link (a link to a paper DOI landing page goes through `oa`? No — keep it the
  ladder; academic DOIs inside posts are Phase 10.4's AVeriTeC concern, not v0.4).
- `verify.target_document`: a `str` that is a social URL → `read_post` → `from_post`; a
  non-social URL → `Document` with one paragraph = the page's title as a note and `references=
  (url,)`? Simpler and honest: `check --url <non-social page>` is an error in v0.4 ("give the
  claim as text: `proofpath check -` with the claim, and the page URL inside it"); raw text →
  `from_text` + `resolve.find_url`-style link extraction into references (numbered), claims
  paragraph-scoped over the links of their paragraph.
